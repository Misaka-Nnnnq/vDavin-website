03

// A few things to know

Before you start.

Why does vDavin request administrator permission?

Native CPU telemetry uses the bundled monitoring driver. The application manages its service automatically and performs cleanup on normal exit. Administrator permission is requested at startup.

Why is a reading unavailable?

Readings depend on the CPU, GPU, firmware, installed drivers, and Windows support. One unavailable backend does not mean every sensor has failed. A missing reading is shown as unavailable, rather than replaced with zero.

Can I record readings and keep my settings?

Yes. Start background CSV recording in Sensors and choose a save directory. Preferences, favorites, alert rules, and layouts persist between launches. CSV recording starts off each session; charts and statistics cover the current session.

Does vDavin support hardware tuning?

Monitoring is read-only. Hardware tuning, disk SMART health, motherboard / fan sensors, and per-process network traffic are not currently implemented.

Where can I report a problem?

Use the public issue tracker. Include the version and build commit from Settings → About, your Windows version, relevant hardware, and steps to reproduce. Review logs and screenshots before sharing personal paths or device identifiers.

// Project notes

 INTERNAL TEST VERSION

vDavin may contain many bugs, and hardware coverage is still incomplete. Read the reminder shown at each launch.

AI has been deeply involved in this project. All code modifications have been performed by AI, and the code has been PARTIALLY reviewed by humans. This is primarily a toy project and an experiment exploring the safety boundaries of AI-generated code running with elevated privileges. Absolute safety is not guaranteed.

The vDavinIo driver source code is currently kept private by the project maintainers for security reasons.

Built by vDavin Contributors

Application development takes place in a private repository.
